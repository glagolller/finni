# RC2: решение интерфейсной стороны

24.09.2026. Проверены разделы 1–15 предоставленного FINNI_LOGIC_CONTRACT_V0_1_RC2.md и JSON-примеры. Это проверка спецификации, не тест приложения. Исходник сохранен рядом как logic_contract_v0.1-RC2.md без изменений.

## Принято для проектирования и общего каркаса

Flutter/Dart, API 26+, sqflite и локальный JSON; Л владеет единственным каркасом, сборкой, моделями, логикой и БД; Ф — UI. Принимаются имя питомца, сервисы каталогов, preview/confirm, TaskAttemptResult, шесть однократных наград по 5, предупреждение о недостаточном плане нужд, разделение finish/start, поколения профиля и актуальный snapshot при повторе. Новая команда не должна повторно использовать ID другого намерения.

Четыре предложения и три покупки за период приняты как проектное правило. ТЗ §2.1 требует: «за один игровой период нельзя купить все сразу». Предыдущая матрица Ф сузила это до ограничения только доходом — это лишнее условие, оно исправлено. Деньги при этом остаются значимыми: цены предложений по периодам 155/135/165/195/130; свежий доход плюс максимум всех наград — 130. В пятом периоде равенство 130 показывает, почему дополнительное ограничение покупок необходимо. Перенесенные деньги не уничтожаются.

Числовая таблица пяти успешных периодов согласуется: доступно/накопления 30/30, 25/60, 5/90, 15/115, 5/25; сытость/настроение 65/84, 65/100, 70/100, 80/100, 85/100. Это расчет документа, а не пройденная игра.

## Предложения Ф для общей конфигурации и UI

- Предлагаемый applicationId: `ru.finni.pet`; это кандидат команды, доступность имени в магазине не проверена. Л фиксирует его до первой подписанной сборки.
- Формы `pet.form.01` (округлый), `.02` (ушки), `.03` (хохолок); палитры `pet.palette.01` (мятный/точки), `.02` (абрикосовый/полосы), `.03` (сиреневый/звезды). 3×3 комбинации различаются цветом и узором. UI содержит визуальные ресурсы, Л проверяет эти ID; для pre-profile выбора согласовать общий список констант в contracts.
- normal после пятого периода: предложено циклически повторять ассортимент 1–5, продолжая номер периода; demo остается закрытым после пяти. Подтверждение Л требуется до реализации normal.
- Удаление: явно показать выбранный профиль и действие, ввести «УДАЛИТЬ»; reset demo — «СБРОСИТЬ». Поддержать отмену без изменений. Это предложение для точного confirmationText.
- Не показывать переключатель purchaseConfirmationEnabled, пока его выключение ничего не меняет. Обязательные подтверждения всегда сохраняются.
- Версии Flutter и зависимостей выбирает и записывает Л вместе с первой воспроизводимой сборкой, Ф использует те же версии.

## Что делать дальше без нового общего согласования

Ф начинает макеты и карту переходов сейчас. Л может подготовить единственный каркас и общие модели в logic/bootstrap после поручения своего пользователя; неизвестные детали не заполнять молча. Исправления R1–R6 прислать одним патчем к RC2, без повторной переписки обо всех принятых пунктах. До этого API является принятой архитектурной основой с перечисленными открытыми деталями, а не полностью замороженной спецификацией.
