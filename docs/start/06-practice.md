# Два индивидуальных отчета и дневника

## Реквизиты и границы достоверности

Персональные реквизиты Ф находятся в локальных бланках вне репозитория. В бланках период практики 01.09–30.12.2026; даты и сведения руководителя подтвердить перед выпуском. ФИО, группа и личные подписи в эту общую версию не включены.

Участник сообщил, что хакатон засчитывается в практику даже при завершении проекта 29.09. Это принимается как исходное условие планирования. Оно не дает основания самостоятельно менять официальные даты или заполнять работы за будущие месяцы. ФИО, группа, руководитель, даты и собственный бланк Л пока отсутствуют. Использовать явные поля «уточнить», а не выдуманные сведения.

В отчете заключение содержит слово «производственной», хотя титул относится к учебной практике. При заполнении согласовать термин со всем документом. В дневнике индивидуальное задание «Изучение объекта автоматизации», план 2+4+4+2 дня; не выдавать расширенный план хакатона за утвержденное руководителем индивидуальное задание. Предлагаемую тему и детализацию согласовать при необходимости по правилам вуза.

## Предлагаемые темы

- Ф: «Проектирование и реализация пользовательского интерфейса мобильного приложения для формирования финансовых навыков детей».
- Л: «Проектирование игровой логики и локального хранения данных мобильного приложения для формирования финансовых навыков детей».

Один продукт допустимо описывать в двух отчетах. Общие факты должны совпадать; индивидуальные цели, выполненные работы, доказательства и выводы различаются. Чужую часть описывать как командный контекст с явным авторством.

## Структура в пределах предоставленного бланка

| Раздел | Отчет Ф | Отчет Л |
| --- | --- | --- |
| Введение | Дети 7–11 лет, проблема понимания финансовых последствий, роль понятного интерфейса | Ограниченные ресурсы, согласованность расчетов, локальность и воспроизводимость игры |
| Цель и задачи | Анализ сценариев, проектирование экранов, реализация, подключение логики, проверка удобства | Моделирование данных и правил, хранение, сценарии обучения, демо, проверки |
| Теория | Возрастная уместность, навигация, доступность, обратная связь, компоненты UI | Локальная архитектура, данные/связи, операции бюджета, целостность, разделение контента |
| Этапы проектирования | Карта требований, путь ребенка/взрослого, схема экранов, первые макеты, выбор оформления | Модели предметной области, схема БД, цикл периода, формулы и контракт |
| Практическая реализация | Реальные экраны, обработка состояний, интеграция, изменения относительно макетов | Реальные модули, схема хранения, операции, сохранение/сброс и контент |
| Проверка | Телефон, навигация, текст/элементы, размеры экрана, сценарий и найденные дефекты | Корректные/ошибочные действия, границы сумм, перезапуск, демо и рост |
| Заключение | Фактически выполненные задачи, освоенные приемы, ограничения личной части | Фактически выполненные задачи, освоенные приемы, ограничения личной части |
| Источники | Прочитанные источники требований, UI, платформы и использованных библиотек | Прочитанные источники требований, хранения, платформы и контента |
| Приложения | Макеты до/после, дополнительные экраны, протоколы, ссылки на версии | Схемы, таблицы экономики, тест-кейсы, примеры контента, ссылки на версии |

Не устанавливать вымышленный норматив объема страниц. Объем определяется бланком, методичкой и достаточностью раскрытия работ. Отдельный технический документ хакатона не заменяет индивидуальные отчеты.

## Иллюстрации и промежуточные результаты

| Этап | Материалы Ф | Материалы Л |
| --- | --- | --- |
| Требования | Таблица экранов и сценариев, схема навигации v1 | Предметные сущности и требования к расчетам |
| Проектирование | Первоначальные макеты и обоснования | Логическая модель БД, цикл периода и правила v1 |
| Первый результат | Создание питомца, главный, бюджет; пометка тестовых данных | Создание профиля, операции бюджета, первые проверки |
| Интеграция | Скриншоты на реальном состоянии, найденные ошибки | Изменения контракта, сохранение и обработка ошибок |
| Доработка | Сравнение макета и финального экрана с причиной изменения | Изменения схемы/формул с причиной и проверкой |
| Завершение | Итоговые экраны и отчет физической проверки | Итоговая модель, протоколы и описание версии |

В бланке предусмотрена схема БД: в отчете Ф включить согласованную схему Л как часть командной архитектуры с подписью об авторстве. В отчете Л аналогично можно использовать схему UI Ф. В обоих отчетах присутствует схема приложения и объяснение места личной работы.

Каждый рисунок имеет номер, название, ссылку в тексте, дату/версию результата. Макет не называется реализованным экраном. Схему обновить при изменении архитектуры. Скриншоты без реальных данных детей. Фрагменты кода включать только если они помогают объяснить собственную часть.

## Дневники

Заполнять по фактическим датам, используя журнал `10-evidence.md`; исходный бланк допускает указание периода. Не распределять задним числом будущие задачи по всем дням. Пометки про ежедневность, воскресенья и еженедельную проверку сверить с требованиями руководителя.

Примеры формулировок, допустимые только после выполнения:

- Ф: «Проанализированы требования к главному экрану; подготовлена схема переходов и первоначальный макет. Результат: …».
- Л: «Описаны сущности профиля и операций; подготовлена логическая модель локальной базы. Результат: …».
- Ф: «Проверена навигация на устройстве …; обнаружено …, исправлено …».
- Л: «Проверены недостаток средств и повторное подтверждение покупки; фактический результат …».

В журнале различать: участник проверил/спроектировал, агент подготовил код/черновик, руководитель дал замечание. Итоговый способ указания ИИ должен соответствовать выясненным правилам вуза и конкурса. Не приписывать студенту тест, исследование или самостоятельное написание, которого не было.

Подписи, оценки, печати и заключения руководителей не заполняются за них. Поля сведений руководителя заполняются лишь подтвержденными данными.

## Реестр источников

Создать отдельный список реально прочитанного для каждого отчета. Начальные источники S1–S6 перечислены в `01-scope.md`. Для внешних источников перед цитированием открыть конкретную страницу, записать название, автора/организацию, дату/версию, URL, дату обращения, использованный раздел. Для локальных конкурсных материалов уточнить допустимое оформление ссылки без публикации закрытого файла.

План поиска, пока не готовая библиография: Единая рамка компетенций 05.03.2026; «Открытый бюджет Москвы»; «Финансовая культура» Банка России; официальная документация выбранной платформы и хранения; рекомендации Android по доступности; инструкция RuStore; лицензии реально использованных библиотек/ресурсов. Не включать источники только для количества и не приписывать им непрочитанные утверждения.

## Приемка учебного комплекта

- Два DOCX отчета по соответствующим бланкам и два DOCX дневника; PDF дополнительно, если нужен вузу.
- Подтверждены реквизиты, вид и даты практики; нет полей-заглушек в сдаваемом тексте, кроме полей руководителей.
- Присутствуют предметная область, цели, проектирование, схема приложения, промежуточные результаты, реализация, проверки, выводы и источники.
- Разделен личный вклад; общие факты согласованы; цифры и функции соответствуют итоговой версии.
- Оглавление, нумерация, подписи, переносы и изображения проверены после рендеринга документов.
- Записи дневника опираются на журнал; нет выдуманных работ, подписей или результатов.
