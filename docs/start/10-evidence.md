# Шаблоны фиксации результатов

Это пустые формы для будущей работы. Все поля в угловых скобках заменяются фактическими данными. Незаполненные шаблоны не являются доказательством выполнения.

## Предлагаемая структура хранения

```text
docs/
  decisions/                 согласованные решения с датами
  contracts/                 версии соглашения UI и логики
  practice/frontend/         записи и черновики Ф
  practice/logic/             записи и черновики Л
evidence/
  frontend/YYYY-MM-DD/        макеты и снимки экрана Ф
  logic/YYYY-MM-DD/           схемы и проверки Л
  integration/YYYY-MM-DD/     общие проверки конкретной версии
delivery/
  intermediate/              опись промежуточной сдачи
  final/                     опись финальной сдачи и ссылки
```

Большие APK/видео удобнее хранить в согласованном хранилище релизов, а в Git — опись, версию и ссылки. Персональные заполненные учебные документы и закрытые исходники ТЗ держать в отдельной непубликуемой папке. Правило публикации определяется согласованным доступом, не названием каталога.

## Протокол проверки

| Поле | Значение для заполнения |
| --- | --- |
| ID теста, требования | <ID и связанные строки матрицы> |
| Дата, исполнитель | <кто действительно выполнил> |
| APK/коммит/версия контракта | <конкретная проверенная версия> |
| Устройство/эмулятор | <модель, Android, ОЗУ, ширина/настройки шрифта> |
| Исходные данные | <профиль, период, остатки, цель> |
| Шаги | <воспроизводимая последовательность> |
| Ожидаемо | <проверяемый результат> |
| Фактически | <наблюдение, значения до/после> |
| Статус | <не выполнялся / пройден / не пройден> |
| Доказательство | <скриншот, запись, лог, отчет теста> |
| Дефект и повторная проверка | <ссылка, исправленная версия и факт повторного прогона> |

Минимальные группы проверок: план в пределах/сверх бюджета; покупка доступная/недоступная/отмена; пополнение/снятие/отмена; повторное действие; успешное/ошибочное задание; пять периодов и три стадии; все сохраняемые поля после запуска; сброс/удаление; отсутствие сети; главное окно 360 dp и увеличенный шрифт; время запуска/отклик; установка release APK; полный сценарий А.

Предложение измерения производительности: на одном указанном устройстве записать условия и несколько запусков/действий, привести наблюдаемые значения и метод измерения. Не выдавать приблизительный визуальный замер за точную инструментальную метрику. Порог из ТЗ: запуск ≤5 с, визуальный отклик ≤1 с.

