# Первая реализация UI поверх каркаса

Ветка frontend/first-ui основана на logic/bootstrap (8221b81), а не на независимом flutter create. Владение pubspec, Android, contracts и игровым контентом остается у Л.

## Реализовано в этой порции

- FinniApp принимает LogicService через конструктор.
- Создание профиля: игровое имя, выбор из bootstrap-форм/палитр, 9 визуальных сочетаний, normal/demo, команда createProfile. Существующие профили открываются через listProfiles/loadState.
- Главный экран отображает снимок: деньги, копилка, цель, состояние, рекомендованное задание и переходы.
- Бюджет: ввод трех целых сумм, preview, явное подтверждение предупреждений, immutable confirmed plan/fact.
- Покупки: каталог, недоступность, эффекты, preview/confirm, отсутствие покупки при отмене или отказе preview.
- Накопления: цель, каталог, смена, пополнение/снятие через preview/command. Подтверждение снятия не отключается.
- Справка, перечень заданий и базовое отображение прогресса.
- GameController: busy, ошибки, защита от старых revision/generation, повтор того же actionId при неопределенном исходе, блокировка новых команд до разрешения повтора. Replay показывается без повторной анимации.

## Еще не реализовано

Интерактивное выполнение шести заданий, завершение/старт периода, получение цели, подробная история и пагинация, взрослый барьер/reset/delete, сохранение настроек. Текущий список заданий прямо сообщает о состоянии разработки. Интеграция экономики/SQLite отсутствует, поскольку Л еще не передал реализацию LogicService. Все соответствующие строки матрицы остаются незавершенными.

## Два способа запуска

Обычная точка входа lib/main.dart пока показывает отсутствие игрового сервиса, без тестовых монет. При получении реализации Л передать сервис в FinniApp(service: ...).

Для разработческого просмотра:

```powershell
flutter run -t lib/main_preview.dart
```

Нужен поддерживаемый настроенный target/device. PreviewService показывает фиксированные снимки RC2.1, не хранит данные и не рассчитывает правила. Реализован точный preview-случай недостатка 40 монет для музыкальной игрушки. Другие неподдерживаемые операции явно сообщают об отсутствии сервиса. Release-запуск main_preview.dart запрещен проверкой kReleaseMode.

Каркаса web/windows в проект не добавлено. Для UI-тестов Android SDK не нужен; APK и запуск на телефоне требуют отдельного Android toolchain.

## Контракт подключения для ДК

Ф не меняет lib/contracts. Вызовы передают profileId, generation/revision исходного preview, уникальный actionId и явно принятые предупреждения. Команда при staleState не отправляется автоматически повторно; пользователь снова открывает предпросмотр. Ошибки I/O допускают повтор того же объекта команды. Успех отображается после ActionResult, без оптимистического списания.

Не заменять main_preview.dart рабочей экономикой. Реальный сервис подключить в main.dart согласованно с Ф; адаптер сохраняется отдельно для UI-проверок и не используется в релизном пути.
