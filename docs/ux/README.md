35 представлений: E01–E13, D01–D04, T1–T6 и 12 дополнительных состояний. Это демонстрация расположения элементов и переходов. Формы не вызывают сервис, покупки не списывают деньги, задания не проверяются, настройки не сохраняются. Каждое состояние — самостоятельный пример; переходы между ними не образуют достоверную игровую сессию. На ошибках и успешных действиях показаны разные заранее подготовленные примеры.

Для просмотра одного телефона добавить `?device=1#E03` к адресу HTML; обычный режим показывает пояснения. Ширина телефона в CSS — 360 px, что не заменяет испытание 360 dp в Flutter. Длинные страницы и крупный текст прокручиваются. Скриншоты относятся к HTML-макету, не к APK.

## Визуальное решение

Спокойный светлый фон, тёмно-зелёный текст и основные кнопки; тёплое жёлтое предупреждение без пугающей красной заливки. Белые карточки отделяют деньги, цель и задачу. Системный шрифт не требует загрузки. Основной текст 16 px, заголовки 23 px, кнопки не ниже 48 px. Цвет никогда не является единственным обозначением ошибки или категории.

Питомец — простая собственная векторная иллюстрация, созданная кодом при подготовке этого проекта. Нет внешних картинок, шрифтов, трекеров или сетевых библиотек. Финальная графика Flutter может использовать эту геометрию после выбора формата совместно с Л; новые зависимости Ф самостоятельно не добавляет.

Макеты достаточно просты для учебного проекта: карточки, стандартные формы и ясные переходы. Нельзя выдавать макет за завершенную функцию или приписывать проверку детям/пользователям, которой не было.

## Для отчета и дневника

Ф: предметная область и пользовательские роли → карта переходов → варианты внешности → макеты → обоснование отображения денег/цели/обратной связи → проверка в браузере. Использовать три PNG как промежуточный результат с датой и пометкой «макет v0.1».

Л: использовать общую схему только как контекст; собственные результаты — модели, таблицы, экономика, транзакции, фикстуры, тесты и сборка после их выполнения. Эти макеты не являются индивидуальной работой Л. Личные реквизиты, подписи и учебные даты сюда не включаются.

Следующий шаг Ф — реализация экранов в единственном каркасе Л после фиксации контрактных деталей; создание второго Flutter-проекта не требуется.
